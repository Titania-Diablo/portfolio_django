Portfolio Django Project - Beginner Explanation

This project is a simple Django portfolio website.
The goal is to show a person’s profile, skills, and projects in a polished layout.

1) How the project is structured

- portfolio_site/settings.py
  This file holds the project-wide configuration.
  It controls things like:
  - project secret key
  - development mode
  - installed apps
  - database config
  - static files

- portfolio_site/urls.py
  This is the main URL router for the project.
  It sends requests to the right app.

- portfolio_app/
  This is the main application folder.
  It contains the pages, routes, templates, and styling for the portfolio.

- portfolio_app/views.py
  This file contains the page logic.
  Each view handles a specific page like home, profile, skills, or projects.

- portfolio_app/urls.py
  This file maps a URL like /profile/ to a view like profile(request).

- portfolio_app/models.py
  This file defines database tables using Django models.
  It is where you would store projects and skills if you wanted to use a real database.

- portfolio_app/templates/portfolio_app/
  This folder contains the HTML pages.
  Django templates are used to display data from Python in the browser.

- portfolio_app/static/portfolio_app/css/styles.css
  This file styles the site with colors, spacing, layout, and responsiveness.

2) How Django works in this project

When someone visits a page:

1. The browser requests a URL.
2. Django checks the URL patterns.
3. The route points to a view function.
4. The view prepares the data.
5. The view renders an HTML template.
6. The browser shows the final webpage.

This flow is:
Request -> URL -> View -> Template -> HTML page

3) Main files and what they do

manage.py
- This is the command script for running the Django app.
- It is used to start the local server and run migrations.

portfolio_site/settings.py
- This is the project’s control center.
- It tells Django which apps are installed and how the app should behave.

portfolio_site/urls.py
- This is the top-level router.
- It includes the app routes and the admin route.

portfolio_app/urls.py
- Makes the route definitions for the portfolio pages.
- Examples:
  - / -> home page
  - /profile/ -> profile page
  - /skills/ -> skills page
  - /projects/ -> project page

portfolio_app/views.py
- Defines the pages the user sees.
- Each view creates Python data structures and then renders a template.

Example:

def home(request):
    featured_projects = [...] 
    stats = [...] 
    context = {"featured_projects": featured_projects, "stats": stats}
    return render(request, "portfolio_app/home.html", context)

This means:
- create a list of projects
- create stats for the homepage
- pass them to the home.html template
- show them on the page

portfolio_app/models.py
- Defines database tables.
- Example classes:
  - Project
  - SkillCategory
  - Skill

These classes tell Django how to store data in SQLite and how each column should behave.

4) Understanding Django templates

Templates are HTML files with Django tags.

Examples:

{{ profile.name }}
- Prints a Python variable into the page.

{% for project in featured_projects %}
- Loops over a list of items.

{% url 'projects' %}
- Generates a URL from a route name.

{% block content %}{% endblock %}
- Lets child templates insert their own page content inside a base layout.

The base template is:
- portfolio_app/templates/portfolio_app/base.html

This file defines the shared layout:
- header
- nav
- footer
- page content area

Then each specific page extends that layout.

5) Styling with CSS

The CSS file lives here:
- portfolio_app/static/portfolio_app/css/styles.css

It controls:
- colors
- layout
- typography
- spacing
- responsive mobile behavior

This project uses a dark-modern design with gradients and card layouts.

6) Why these files matter for learning

If you want to learn to write your own Django code, these are the main things to focus on:

- URL routing: decide what page lives at what URL
- Views: write the logic for the page
- Templates: display data on the page
- Models: store data in a database
- CSS: style the interface

7) Simple beginner mindset

A beginner-friendly way to think about Django is:

- URL = where the page is
- View = what happens on that page
- Template = what the user sees
- Model = what information is stored

8) What this project teaches you

This project is a good starter because it shows:
- project setup
- routing
- page creation
- data in Python dictionaries
- templates with loops and variables
- clean styling with CSS

It is not a large production app, but it contains most of the core Django concepts you need to learn.

9) Next steps to build your own app

A good next step is to build a tiny project like:
- a todo list
- a blog homepage
- a book list
- a contact form

The pattern is always:

1. create a URL
2. create a view
3. create a template
4. pass data into the template
5. style it with CSS

That is how most beginner Django apps are built.

10) Learning takeaway

The most important skill is understanding how data moves through the app:

Python data -> view -> template -> browser

Once you understand that flow, you can build almost any Django app.

This portfolio project is a great foundation because it demonstrates the same pattern in a simple, readable way.
